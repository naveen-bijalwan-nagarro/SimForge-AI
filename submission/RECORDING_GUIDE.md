# CodexForge four minute recording guide

Use the `CodexForge` folder beside this guide for the final ZIP. The recording must be **no longer than four minutes**. The submission freeze is **11:00 AM on Saturday, 10 October 2026**. The video, `SimForge-AI-code.zip`, the submission overview and any optional screenshots must be inside one `CodexForge.zip`; upload that outer ZIP to Google Drive, enable the required viewer access, and submit its shareable link in the form. The code ZIP itself is the technical artifact; a GitHub link is not needed for judging.

## Prepare the actual run

1. Install dependencies with `.\setup.cmd` before recording, then build the React UI if needed. For the video, run `.\start.cmd` from the project folder in PowerShell and show its local URL followed by the loaded app. `start.cmd` calls `scripts/start.ps1 -Open`; it serves the built React UI and API together at `http://127.0.0.1:8000` by default and rebuilds the UI if stale. Trim genuine waiting time in the edit. Crop or blur the development credentials printed in the terminal. Use separate browser profiles or a private window for Admin / Trainer and Learner; ordinary tabs share the same login cookie.
2. In Admin / Trainer → Scenario Lab, paste `samples/sample1/admin_prompt.txt` and select the operations brief and sensor charts in `samples/sample1`. Preview their extracted text. The privacy examples document is optional if you want to show recognized PII types and counts. Never use real personal or customer data.
3. Check that **Codex CLI** is signed in and available before saying Codex authored a draft. Generate a FactoryPulse draft ahead of recording, retain its source and timestamp, and leave it **unpublished** for the recording. Keep the Admin prompt and references selected in an open tab because those selections reset when the authoring page remounts. If generation is slow, show the saved draft and say when it was created. If the source is `openai_api` or `manual`, name it accurately and do not call it a Codex-generated draft.
4. Rehearse the learner path on a separate synthetic exercise so the recorded sequence is familiar. For the recorded FactoryPulse journey, use one published scenario and the same learner run through notification, baseline, diagnosis, decision, outcome and post-check. Use 60 work items, seed 2026 and a 35-minute simulated horizon if those settings remain available.
5. Hide desktop notifications, API keys, passwords and the Admin prompt while the learner diagnoses the hidden cause. Set browser zoom so labels and score bars remain readable. Record at 1080p if available, with the cursor visible and microphone audio checked.

## Editing and final check

- Keep the exported file under **4:00**; target 3:50–3:58. Export an MP4 with readable text and clear voice. Do not speed up narration merely to fit the limit.
- Show the actual app. Cuts may remove waiting, but do not splice different scenario or learner runs into one claimed round trip. If a draft was created earlier, say so. If Codex is unavailable, use a clearly labelled fallback and explain Codex's demonstrated development or earlier authoring contribution only where supported.
- If the team obtains a real user interview or pilot result before the deadline, replace the validation sentence with one sourced fact and show its date or source. Otherwise keep the honest “no measured customer pilot yet” line.
- The optional two screenshots worth capturing are the Admin Security review receipt and the learner practice report. Review them for credentials, personal information and hidden answers before including them.
- Confirm `CodexForge/SimForge-AI-code.zip` contains the final source version and that the hash in `TECHNICAL_REFERENCE.txt` matches it. If the application code changes, rebuild this inner ZIP and update the hash. The code ZIP excludes `.venv`, `node_modules`, generated UI assets, caches, local runtime data and secrets; `setup.cmd` restores dependencies.
- Put the final `SimForge_Demo.mp4` inside `CodexForge`, alongside the code ZIP, overview and technical reference. Zip the **CodexForge folder**, name the outer archive `CodexForge.zip`, verify it contains both the video and code ZIP, open the outer ZIP once, then upload it to Google Drive. Test the viewer link in a private browser before submitting the form.
